## How work is done here

- **Gates** (from `apps/web`), all must pass before a push:
  - `NODE_OPTIONS=--max-old-space-size=6144 npx tsc --noEmit -p .`
  - eslint on the files you changed
  - `node scripts/check-no-em-dash.mjs`, `node scripts/check-css-tokens.mjs`, `node scripts/check-valuation-words.mjs`, `npm run -s check:claims`
  - `npx vitest run --project unit` and `--project dom` (at least the areas touched)
- **New routes** need entries in `src/lib/nav/route-parents.ts` and `src/lib/nav/route-labels.ts`.
- **Capsule shapes** need an entry in `PILL_ALLOWED` in `scripts/check-css-tokens.mjs`.
- **Database changes**
  1. Apply with Supabase MCP `apply_migration`.
  2. Save the same SQL as `supabase/migrations/<version>_<name>.sql`, using the version the database recorded (`select version from supabase_migrations.schema_migrations order by version desc limit 1`).
  3. Record it: `node scripts/check-migrations.mjs --record <file>`.
  4. Drafts go in `supabase/migrations/pending/`.
  5. Statements that drop or delete may stall on a 60s confirmation. Avoid needless drops, or give the founder the SQL to paste.
- **Database checks (probes)**
  - Live probes are in `supabase/tests/probes/`; probes not yet run live go in `supabase/tests/probes-pending/`.
  - Contract: one `do $$ ... $$` block ending `raise exception 'PROBE_OK <id>'`; failures raise `'PROBE_FAIL <id>: ...'`.
  - Everything is rolled back, switches are set inside the transaction, and live values are never asserted.
  - CI runs them against live on every push.
- **New pg_cron jobs** must also be added to `PG_CRON_JOBS` in `apps/web/src/lib/admin/reads/jobs.ts`, to the job table in `docs/ADMIN_CONSOLE.md`, and to the count ("41 pg_cron jobs" today).
- **Sandbox network limits**: MapTiler, Payluk, LiveKit and Termii cannot be reached from the cloud sandbox. Check providers from production at `/admin/operations/providers` (console, Operations, Provider checks).
