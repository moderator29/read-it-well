## 1. Item 4, the contrast probe: REPAIRED, and the headline is withdrawn

### What was wrong with it, and one part of the received diagnosis is wrong too

The received account is that `probe-contrast.mjs` takes one
`page.screenshot({fullPage:true})` per route and that "past roughly 4,700 CSS
pixels the capture silently stops containing content".

**The single-capture design is real and is the right thing to have removed. The
4,700px cut did not reproduce on this box, and I looked for it deliberately
before repairing anything.** `scratchpad/fullpage-cut.mjs` shoots a route full
page, reads the PNG back band by band and counts distinct colours per 400px
band. On `/preview/p3/admin-businesses`, the tallest harness route at
**8,337 CSS px**, the PNG is 780x16674 device px and **every band down to
cssY 8,200 holds hundreds of distinct colours.** Same on `/preview/g5/all`
(5,302px) and `/preview/f5/admin-desks` (5,182px). Only **3 of 115** harness
routes exceed 4,700px at all.

So the blank-capture mechanism is not what produced "43 of 84 did not
reproduce". Something else did, and three things did, all found by opening the
crops rather than by reading the file.

### The three real faults, each observed

**ONE, and it is the largest. The probe measured an element's LINE BOX rather
than its words.** A `<p>` 222px wide holding "5 photos" is nine tenths ground.
The glyph colour then covers four pixels in a thousand, falls under the
half-a-per-cent floor that stops a stray pixel being called ink, and the
histogram is left with the ground and one shade of the ground. The probe
reported **the ground against itself, 1.00:1**, on text that is plainly legible.

Measured on `/preview/f5/agent-listings`, dark, the words "5 photos":

| | |
|---|---|
| element box | 222 x 15 CSS |
| ground | `rgb(0,3,21)` at **57.2%** of the box |
| glyph | `rgb(143,157,197)` at **0.4%** of the box |
| probe said | **1.00:1** |
| the crop, opened by hand | pale blue on navy, plainly legible |

Every short label in a wide box failed this way, in both themes. It now asks the
browser where the glyphs are, with a `Range` over the element's own text nodes
and `getClientRects()`, padded by a quarter of the type size.

**TWO. The ink was searched for in the sixty most common colours only.** An
antialiased glyph core is rarely in the top sixty. The whole histogram is
searched now, against the same floor.

**THREE. Opacity compounds and the probe asked only the element.** A closed
sheet, a fading scrim and a panel behind a modal all draw their words as a wash,
and the leaf's own opacity is 1 in all three. `/preview/g1/sheet` in light
reported "Notifications" as `rgb(237,240,246)` on `rgb(236,239,244)`: a statement
about a sheet that is not open. Effective opacity is now the product down the
ancestor chain.

### What the repaired probe does instead

It shoots the **viewport**, steps half a screen at a time, and measures only
elements that are on screen in the frame being read. Half a screen is the
covering argument: any element no taller than the step lands wholly inside the
viewport at some position, so the ordinary pass can insist on whole elements and
still see everything. Elements taller than the step get their own frame and are
marked `partial`. Anything still unreachable is **named in `unreached`**, because
"could not look" and "passes" are different facts. It also refuses a blank frame,
a non-2xx, a redirect, and a `notFound()` body served at HTTP 200. Every element
is measured exactly once.

## 2. Item 5, the shape law: RUN PROPERLY, AND IT DOES NOT RETURN ZERO

The definition of done asks for `compare-surface.mjs --shape-sweep` to return
zero. The one genuine run covered 9 routes of about 98.

**It covered nine because it could not survive a tenth.** `openSurface` refuses
correctly on a non-2xx, on a redirect and on a page that never revealed, and

open. A sweep that dies on route ten cannot answer its own definition of done
either way. Refusals are now collected, printed with their reason, and counted
as routes nothing is claimed about.

Run over **163 routes** (115 preview harness plus the 48 product routes that
open without a session), at 390 and 1536, in dark and light:

| | |
|---|---|
| routes asked for | **163** |
| route/width/theme refusals | **20** |
| **BREACHES, a text-bearing control drawn as a capsule** | **48** |
| worth an eye, over 0.35 and not yet a capsule | 421 |
| round icon-only controls | 384 |

**The 48 breaches are all one thing, on two pages.** Every one is `.nf-badge`
carrying a word, at a drawn radius of exactly half its short side:

```
/preview/g1/sheet @390 dark  nf-badge  "In Review"  101x30  radius 15.1px  ratio 0.50
```

Six badge variants (In Review, Pending, Approved, Completed, Rejected,
Verified) x two routes (`/preview/g1/sheet`, `/preview/g1/surfaces`) x two

its own comment that "no surface outside `app/(dev)/preview/g1/` passes one".

**So the honest answer to "does the shape law return zero": no, it returns 48,
and all 48 are the two harness pages that exist to demonstrate the deprecated
prop.** Whether that closes the item is the lead's call; what is now settled is
that the sweep has been run across every route this environment can reach and
the answer is not zero.

### One instrument bug found while doing it

The sweep printed `ratio 33.14` for those badges. CSS clamps a radius that would
overlap to half the short side, so `border-radius: 999px` on a 30px badge DRAWS
15px. The sweep divided the declared 999 by 30. No corner on this platform is
thirty-three times its own side. The verdict was right and the figure beside it
was nonsense; it is clamped now and reports the honest **0.50**.

## 3. Item 2, the rate limits: CONVERTED. A money call site refused and I watched it

**Fourteen money call sites carried rate limits and not one had ever refused
anything. Two now have, deliberately, and the refusal was observed end to end.**

### What had to be built to see it

The live database is behind the egress block (section 0) and the MCP connection
is `supabase_read_only_user`, which **cannot execute the function**:
`has_function_privilege` on `public.consume_rate_limit` is false for it and true
for `service_role`. So the refusal was produced against a real Postgres 16 on
this box carrying **the live function body**, pulled verbatim out of the live
project with `pg_get_functiondef()`, and reached through a PostgREST-shaped door
so that the product's own `supabase-js` client, its own `service-rpc` module,
its own `countRouteFailure` and its own route handler are all in the loop.
**Nothing about the product is stubbed. Only the database's address changed.**

One thing had to be discovered the expensive way first: `NEXT_PUBLIC_*` is
inlined at BUILD time, so overriding the URL at runtime did nothing and the
first 34-request run answered 401 thirty-four times with **zero RPC calls made**.
The whole thing had to be rebuilt against the new URL. That is worth knowing for
anybody else who tries this.

### What is converted and what is not

anywhere says so.** I watched exactly that happen for 34 consecutive requests
before the rebuild. The direction of the failure is the right one and is well
argued in the file; the silence is the part worth a second look.

### Read this before reading the list

**8 of those 15 are the egress block, not the product.** `/listing/<a real
published id>`, `/stay/<id>`, `/restaurant/<id>`, `/post/<id>`,
`/rent/move-in/<id>` and `/around/lekki` all answer HTTP 200 with the not-found
body **because the server cannot reach the database to find the row.** Written
down as product defects they would be six false accusations, and the most
alarming-looking finding in this whole run would have been one of them.

### What genuinely broke or surprised

| # | route | what happened |

| 1 | **`/sign-in`** | Signed out, in a browser, **lands on `/welcome`**. The front door does not draw the sign-in screen. |
