# The Hundred: the build ledger

The running record of building `docs/THE_HUNDRED.md`. Every V-number, what shipped, the evidence it works, and its
state. Updated as work lands.

**States.** SHIPPED: built, adversarially reviewed by a second agent, and every gate green on the build branch.
PARTIAL: some of it shipped and the entry says which half. DEFERRED: not built, with the reason. FOUNDER: built to the
boundary and switched off, waiting on one of the sixteen founder decisions, with the one step that turns it on.
AUDIT: owned by the audit session and not touched here.

**Where it lives.** Branch `claude/vallo-hundred-recommendations-xclnva`. Database changes are migration files proven
against the live schema by a probe that ends in a deliberate raise (nothing persists); they apply when the branch
merges to `main`.

## SCUML: which code discharges which obligation

These rows cover the SCUML-EFCC AML/CFT checklist for DNFBPs (Money Laundering (Prevention and Prohibition) Act 2022), as read in `docs/AML_COMPLIANCE_GAP.md`. Nothing here is legal advice; the solicitor confirms it. Each row exists so the founder can show an examiner which code discharges which item, and each migration and module header names its item. Everything lives on the staff-only desk at `/admin/compliance` (one lane per item, behind `requireAdmin`). Nothing is shown to the member: there is no badge, no score and no changed wording, so a person under review is never tipped off. Every screening, decision, classification and filing is an append-only row that records who and when, and is kept five years (item 11). `docs/RETENTION_SCHEDULE.md` lists the rows, and no purge deletes them. Every decision that closes a hit, clears a PEP, overrides a class, files or declines an STR, or marks a threshold report filed needs a second staff member, who may not be the one who decided (item 19).

| SCUML item | Obligation | What discharges it (migrations, functions, tables, files) | Evidence | State |
|---|---|---|---|---|
| 17 | Beneficial ownership where the customer is an intermediary | Migrations `20260924171000`, `171100`, `171200`.
